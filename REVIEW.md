# Release review

This release replaces the previous exam/drill/study menus with five fixed 75-question exams, learning and timed modes, and contextual instruction. The bank covers every listed AIP-C01 skill while preserving the weighted five-domain composition of each form.

## Content controls

- 375 distinct scenarios, unique IDs and question-specific four-stage SVG diagrams.
- 98/98 listed skills represented; 20/20 tasks in every form.
- Per-option rationales, trusted references and task-level theory for every question.
- 20 practical exercises with prerequisites, expected evidence, verification and cleanup; six include CLI or Logs Insights examples.
- Answer order is shuffled. An editorial length audit avoids making either the shortest or longest choice a reliable answer cue.
- Explicit distinction between raw practice accuracy and AWS scaled scoring, lesson exposure and mastery, and guided exercises versus actual AWS execution.

## Validation

`npm test` covers content invariants, weighted non-overlapping forms, every skill and teaching module, exact-set scoring, answer locking, confidence, retries, timer restoration, corruption rejection and storage failure handling.

`npm run test:browser` covers actual UI submission/cancellation, wrong-answer diagnosis, explanations hidden during timed attempts, persistence, timeout, lesson/exercise progress and all 375 rendered lessons at desktop/mobile widths. It checks SVG text bounds, source links and runtime errors. The coverage report is generated by `npm run coverage`.

The static app needs no backend or AWS credentials. GitHub Pages uses the existing main/root configuration. Question data is intentionally client-side, so this is a study application rather than a secure examination system. Browser storage retains the latest full attempt and a limited summary history, not a cloud account or cross-device record.

See [research decisions](docs/RESEARCH.md) and the [coverage map](docs/COVERAGE.md) for the content scope and limitations.
